Generate `HUMAN_OVERVIEW.md` for the target repository.

Audience:
A developer or technical hiring manager who wants to understand the repository quickly without reading every file.

Required structure:

# Human Overview

## What this project does
Explain the project in plain English.

## Why it exists
Explain the problem it appears to solve. Mark this as inferred if the repository does not explicitly say it.

## Main components
List the most important parts of the repo. For each component:
- name
- purpose
- important paths

## How the system works
Describe the main workflow or lifecycle. Use numbered steps if helpful.

## What to read first
Give a practical reading order with paths and reasons.

## How to run or use it
Summarize setup/run/test commands if discoverable. If not clear, say so.

## What is already clear
Mention strong signals from the repo: tests, docs, APIs, configs, examples, CI, Docker, etc.

## What is unclear
Mention missing or ambiguous parts without being harsh.

## One-minute summary
Give a concise recruiter-friendly summary of the repo.
